# GPS PDOP Analysis Tool

A comprehensive Position Dilution of Precision (PDOP) analysis tool for GPS satellite constellations using GMAT (General Mission Analysis Tool) and Python post-processing.

## 🛰️ Overview

This project simulates a 24-satellite GPS constellation and calculates PDOP values for a ground receiver over a 24-hour period. PDOP is a critical metric for assessing GPS positioning accuracy and satellite geometry quality.

## 📋 Features

- **Full GPS Constellation Simulation**: 24 satellites in 6 orbital planes (Walker Delta pattern)
- **Realistic Orbital Parameters**: 
  - Semi-major axis: 26,560 km
  - Inclination: 55°
  - Circular orbits (e = 0)
- **Ground Receiver Configuration**: Austin, Texas (30°N, 97°W)
- **Elevation Mask**: 5° minimum elevation angle
- **High-Resolution Output**: 1-minute time steps over 24 hours (1,440 data points)
- **Automated Analysis**: Python script for PDOP calculation and visualization

## 🚀 Quick Start

### Prerequisites

**GMAT (General Mission Analysis Tool)**
- Download from: [https://gmat.gsfc.nasa.gov/](https://gmat.gsfc.nasa.gov/)
- Version: R2020a or later recommended

**Python Dependencies**
```bash
pip install numpy pandas matplotlib
```

### Installation

1. Clone this repository:
```bash
git clone https://github.com/yourusername/gps-pdop-analysis.git
cd gps-pdop-analysis
```

2. Ensure GMAT is installed and accessible

### Running the Analysis

**Step 1: Run GMAT Simulation**
```bash
# Open GMAT and load the script
# File > Open > PDOP_analysis.script
# Then run the mission (or use GMAT in batch mode)
```

This generates two CSV files:
- `GPS_Positions.csv` - All 24 satellite positions in ECEF coordinates
- `Receiver_Position.csv` - Ground receiver position in ECEF coordinates

**Step 2: Run Python Post-Processing**
```bash
python gmat_pdop_postprocess.py
```

This produces:
- `PDOP_Results.csv` - Time series of PDOP values and visible satellites
- `PDOP_Analysis.png` - Visualization plots

## 📊 Output Interpretation

### PDOP Values
- **< 2.0**: Excellent geometry
- **2.0 - 5.0**: Good geometry
- **5.0 - 10.0**: Moderate geometry
- **> 10.0**: Poor geometry

### Expected Results
- Typical PDOP range: 1.5 - 4.0
- Visible satellites: 3-6 at any time (varies with constellation geometry)
- PDOP variations throughout the day due to changing satellite geometry

## 🔬 Technical Details

### Coordinate System
- **All outputs in Earth-Fixed (ECEF) frame**
- Origin: Earth's center of mass
- X-axis: Points to 0° latitude, 0° longitude
- Z-axis: Points to North Pole
- Units: kilometers

### PDOP Calculation Method

1. **Geometry Matrix Construction**:
   - For each visible satellite (elevation > 5°):
   - Compute line-of-sight unit vector: **u** = (**sat** - **rec**) / ||**sat** - **rec**||
   - Build row: [-u_x, -u_y, -u_z, 1]

2. **Covariance Matrix**:
   - **Q** = (**H**ᵀ**H**)⁻¹

3. **PDOP Calculation**:
   - PDOP = √(Q₀₀ + Q₁₁ + Q₂₂)

### GPS Constellation Design

**6 Orbital Planes, 4 Satellites Each:**
- Plane 1: RAAN = 0°   (GPS1-4)
- Plane 2: RAAN = 60°  (GPS5-8)
- Plane 3: RAAN = 120° (GPS9-12)
- Plane 4: RAAN = 180° (GPS13-16)
- Plane 5: RAAN = 240° (GPS17-20)
- Plane 6: RAAN = 300° (GPS21-24)

**True Anomalies per Plane:** 0°, 90°, 180°, 270°

## 🐛 Troubleshooting

### Error: "time data does not match format"
**Solution**: The script now handles multiple date formats automatically. If issues persist, check that your GMAT output includes the `GPS1.UTCGregorian` column.

### Error: "Column not found"
**Solution**: Verify that GMAT successfully generated both CSV files with the correct column headers.

### PDOP values seem unrealistic (> 100,000)
**Cause**: Fewer than 4 visible satellites at that epoch
**Solution**: This is expected behavior. Consider:
- Changing receiver location
- Adjusting elevation mask
- Verifying constellation configuration
